## 2. Security: where it stands

Sound. No change needed for:
- **Injection:** none possible through the page. All text goes through `esc()`/`gloss()`; the injection pass found
  nothing; the policy allows scripts only from the site or by exact hash, so injected script or inline handlers would
  not run anyway. There is no database or server for SQL injection to reach; the pipeline's own SQLite queries are
  parameterised.
- **Outside data:** news links must be `https://` (tested against `javascript:` and `data:`); embedded data escapes
  every `<`; feed downloads are size-capped; AI explanations are fact-checked before publishing and escaped on the page.
- **Supply chain:** no runtime dependencies; workflow actions pinned to commit SHAs; least-privilege permissions; one
  secret (NVD key) passed to one step.
- **Saved progress:** treated as untrusted and cleaned; restores only from a file or code the user supplies.

Limits of GitHub Pages (owner decision, not a code change):
- It can't send security headers, so there is no clickjacking protection (`frame-ancestors`), `Permissions-Policy`
  or `Referrer-Policy` header. Low risk here (no logins, nothing to trick a click into), but a scanner such as
  securityheaders.com will grade the site poorly, which matters for a security brand. Fix: put production behind
  Cloudflare (headers via a `_headers` file or a rule). That is a DNS change, so it needs the owner.
- The feedback form relies on a honeypot only. Formspree's own spam filtering covers the rest; add its CAPTCHA only
  if spam arrives.

## 5. Content gap: governance, risk and compliance (GRC)

The site covers frameworks in one paragraph. NIST CSF 2.0 gets a sentence and ISO 27001 a sentence; CIS Controls,
NIST SP 800-61 and 800-63, the Cyber Kill Chain, STRIDE and NIS2 are absent; UK Cyber Essentials is mentioned once.
For a UK site that is the biggest gap. Proposed track (each piece mapped to Security+ 5.x, which lifts that domain):

| Piece | Kind | Covers |
|---|---|---|
| Frameworks in practice | lesson | NIST CSF 2.0 (6 functions, categories, profiles and tiers), ISO/IEC 27001:2022 (ISMS, 93 Annex A controls in 4 themes, certification audits), CIS Controls v8.1 (18 controls, IG1 to IG3), NIST SP 800-53 (US control catalogue), how they map to each other |
| Cyber Essentials | lesson + lab | The UK scheme's five controls (firewalls, secure configuration, user access control, malware protection, security update management), Basic vs Plus. Lab: check an Agency client against the five controls |
| Risk, simply | lesson + lab | Likelihood × impact, risk register, appetite, treat/transfer/accept/avoid, BIA. Lab: build a risk register from a client file |
| Laws you'll meet | lesson | UK GDPR and DPA 2018, Computer Misuse Act 1990 (why "only test what you own"), NIS Regulations / NIS2, PCI DSS v4.0, DORA |
| How attacks are modelled | lesson | Cyber Kill Chain, MITRE ATT&CK, Diamond Model, STRIDE threat modelling |
| Map the control | lab | Crosswalk one control across CSF, ISO Annex A, CIS and Cyber Essentials |
| Audit week | Agency shift | Diagnose for GRC: a client's Cyber Essentials readiness review with evidence to gather and gaps to report |
| Path to GRC Analyst | path | Ties it together; linked from the careers card |

Also worth adding: incident response per NIST SP 800-61 (the IR lesson's lifecycle), and NIST SP 800-63 assurance
levels in the identity lesson.
