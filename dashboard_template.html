CVE Field Guide

Every week thousands of new security bugs are published. Most won't affect you. This guide sorts them by how likely they are to be used against real systems and explains each one in plain English.

Start here

Five terms that unlock this page

CVE

The bug's ID number

Common Vulnerabilities and Exposures. A public catalogue where each known security bug gets a unique ID, so everyone can talk about the same problem.

CVE-2021-44228 is Log4Shell. "2021" is the year the ID was reserved.

CWE

The type of mistake

Common Weakness Enumeration. If a CVE is one specific broken lock, the CWE is the category of lock flaw. Learning the common CWEs teaches you how most bugs happen.

CWE-89 is SQL injection. CWE-79 is cross-site scripting.

CVSS

How bad it could be

A 0–10 severity score based on how the bug is reached and what an attacker gains. It measures worst-case damage, not whether anyone is actually attacking.

9.0–10 Critical · 7.0–8.9 High · 4.0–6.9 Medium · below 4 Low

EPSS

How likely it gets used

Exploit Prediction Scoring System. A model from FIRST that estimates the chance a CVE will be exploited in the next 30 days, using real attack data.

Most CVEs sit below 1%. Anything above 10% stands out.

KEV

Confirmed in the wild

CISA's Known Exploited Vulnerabilities catalogue. A CVE goes on this list only when there's evidence attackers are using it. US federal agencies must patch these by a deadline.

Old CVEs get added too, when attackers rediscover them.

Why this page doesn't just sort by CVSS

Security teams can't patch everything at once. A "critical" bug nobody is attacking can matter less than a "medium" one that ransomware gangs are using today. So every CVE here gets one of five priority levels, checked in this order:

1 · ExploitedOn CISA's KEV list. Patch now.
2 · LikelyEPSS of 10% or more. Attackers are expected to use it.
3 · CriticalCVSS 9.0+. Severe if used, no attacks seen yet.
4 · HighCVSS 7.0–8.9.
5 · OtherLower scores or not scored yet.
